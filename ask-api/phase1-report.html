表字段说明
invite_codes id, code, is_used, used_at, created_at 邀请码表。管理员预生成，用户激活后标记已使用
users id, username, device_id, invite_code_id, is_active, created_at 用户表。device_id 唯一标识设备，邀请码外键关联
conversations id, user_id, title, created_at, updated_at 对话表。一个用户可创建多个对话，默认标题"新对话"
messages id, conversation_id, role, content, command, explanation, danger_level, created_at 消息表。role 区分 user/assistant，danger_level 分 safe/warn/danger

开发过程中解决的问题

1. UserResponse 字段映射错误 已修复

现象：/api/auth/activate 接口始终返回 400 Bad Request。

原因：UserResponse 定义了 user_id 字段，但 ORM 模型 User 的字段是 id。model_validate(user) 无法找到 user_id 属性，抛出 ValidationError（Pydantic v2 中是 ValueError 子类），被 except ValueError 捕获后返回 400。

修复：移除 UserResponse 的 from_attributes，在 auth 端点手动构造响应对象，显式映射 user.id → user_id。

2. 路由前缀重复 已修复

现象：对话接口 URL 变成 /api/conversations/conversations。

原因：conversations 路由文件内 APIRouter(prefix="/conversations")，同时 main.py 注册时 prefix="/api/conversations"，导致双重前缀。

修复：移除路由文件内的 prefix，统一在 main.py 注册时指定。

3. 内存 SQLite 连接隔离 已修复

现象：测试 fixture 中创建的邀请码，在 HTTP 请求中查不到。

原因：内存 SQLite 默认每个连接独立，fixture 用的 db 会话和 client 用的请求会话是不同连接，数据互不可见。

修复：在 conftest.py 的 create_async_engine 中添加 poolclass=StaticPool，让所有会话共享同一个内存连接。

4. Pydantic Config 弃用警告 已修复

原因：Pydantic v2 弃用了 class Config 方式。

修复：所有响应模型改用 model_config = ConfigDict(from_attributes=True)。
