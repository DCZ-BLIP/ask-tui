01 命令安全检查器

safety_checker.py 是 TUI 端的命令执行前安全审查模块。通过正则模式匹配 + AI danger_level 联动，将命令分为三种操作级别：

BLOCK 禁止执行，直接阻止（rm -rf /, mkfs, dd of=/dev/, shutdown 等）
CONFIRM 弹出确认弹窗，用户确认后执行（rm -f, chmod 777, git push --force 等）
ALLOW 安全命令，直接执行（ls, cat, grep, find, git status 等）

1.1 检测维度

检测维度模式数量说明
BLOCKED_PATTERNS15禁止执行的命令模式（格式化、关机、fork bomb 等）
CONFIRM_PATTERNS17需要确认的命令模式（删除、强制推送、远程脚本等）
INJECTION_PATTERNS6命令注入检测（反引号、$()、eval 等）
SENSITIVE_PATHS10敏感目录列表（/etc, /sys, /boot, /dev 等）

1.2 AI danger_level 联动

安全检查器不仅依赖正则匹配，还结合 AI 返回的 danger_level 字段做联动决策：

  • BLOCK 优先：即使 AI 说 safe，rm -rf / 仍然 BLOCK
  • danger 覆盖：AI 判定 danger 的命令，即使无检测风险也要确认
  • warn 确认：AI 判定 warn 的命令，需要用户确认
  • safe 放行：AI 判定 safe 且无检测风险，直接允许执行
设计决策：安全检查器运行在 TUI 端而非服务端，因为命令最终在用户本地执行，检查逻辑应在执行前进行。这也避免了网络延迟影响用户体验。

02 TUI 命令执行功能

在 Phase 2 的三栏布局基础上，新增了 Ctrl+Enter 执行命令的快捷键，以及两个弹窗界面：

2.1 命令确认弹窗（ConfirmScreen）

当安全检查器返回 CONFIRM 时，弹出确认弹窗显示：

  • 即将执行的命令内容
  • 风险项列表（通过 format_risks() 格式化）
  • 危险等级标签
  • 确认/取消按钮（支持 y/n/Esc 快捷键）

2.2 命令输出弹窗（OutputScreen）

命令执行完成后，弹出输出窗口显示：

  • 执行的命令内容
  • 退出码（0=成功，非 0=失败，-1=超时/错误）
  • stdout 完整输出
  • stderr 完整错误信息
  • Esc/Enter 关闭

2.3 执行流程

用户按 Ctrl+Enter
    │
    ▼
获取 current_command（当前预览的命令）
    │
    ▼
check_command(command, ai_danger_level)
    │
    ├── BLOCK ──→ 聊天记录显示"命令被阻止" + 原因
    │
    ├── CONFIRM ──→ 弹出 ConfirmScreen
    │                  ├── 确认 → _execute(command)
    │                  └── 取消 → 聊天记录显示"已取消"
    │
    └── ALLOW ──→ _execute(command) 直接执行
                        │
                        ▼
                 subprocess.run(shell=True, timeout=30)
                        │
                        ├── 成功 → 聊天记录简要输出 + 弹出 OutputScreen
                        ├── 失败 → 聊天记录错误信息 + 弹出 OutputScreen
                        └── 超时 → 聊天记录"超时" + 弹出 OutputScreen

2.4 执行细节

  • 异步执行：使用 asyncio.to_thread(subprocess.run, ...) 避免 TUI 冻结
  • 超时保护：30 秒超时，防止长时间阻塞
  • shell=True：支持管道、重定向等 shell 语法
  • 输出截断：聊天记录中只显示前 5 行，完整输出在弹窗中
  • 错误处理：TimeoutExpired 和 Exception 都被捕获，通过弹窗展示

03 部署配置

3.1 Dockerfile

基于 python:3.10-slim 镜像，利用 Docker 缓存层优化构建。生产环境关闭 DEBUG 和 reload，单 worker 运行。

3.2 Render Blueprint（render.yaml）

配置了 Render 免费套餐部署方案：

  • 套餐：Free（512MB 内存，750 小时/月）
  • 运行时：Python 3.10.12
  • 持久化：1GB 磁盘挂载到 /data，SQLite 数据库存于此
  • 环境变量：ADMIN_API_KEY 自动生成，LLM_API_KEY 手动填写
  • 启动命令：uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1

3.3 .env.example 完善

新增生产环境注意事项：DEBUG 设为 False、ADMIN_API_KEY 改为随机字符串、DATABASE_URL 使用持久化路径、LLM_API_KEY 填入真实密钥。

注意：Render 免费套餐在 15 分钟无请求后会自动休眠，首次请求需要冷启动。对于开发和小规模使用足够，生产环境建议升级付费套餐。

04 PyInstaller 打包配置

通过 PyInstaller 将 ask-tui 打包为单文件可执行程序，方便分发给朋友使用。

4.1 打包配置（ask-tui.spec）

  • 单文件模式：onefile=True，生成一个可执行文件
  • hiddenimports：显式声明 Textual 和 Rich 内部模块
  • excludes：排除 tkinter、matplotlib 等不需要的大型库
  • UPX 压缩：减小输出文件大小

4.2 构建脚本（build.sh）

一键打包脚本，自动检查依赖、清理旧构建、执行打包、验证输出：

chmod +x build.sh
./build.sh

# 输出:
# ✓ 打包成功!
#   输出文件: dist/ask-tui
#   文件大小: 15M
分发前：修改 config.py 中的默认 API 地址为你的线上服务 URL（https://你的域名.com），这样朋友安装后开箱即用，无需手动配置。

07 部署指南

7.1 后端部署到 Render

# 1. 注册 Render 账号 (https://render.com)
# 2. 新建 Web Service，连接 GitHub 仓库
# 3. 选择 "Blueprint" 模式，自动读取 render.yaml
# 4. 在 Environment 中设置:
#    - LLM_API_KEY = 你的智谱 API Key
#    - ADMIN_API_KEY = 自动生成（或手动设置）
# 5. 部署完成后获取 URL: https://ask-api-xxxx.onrender.com

# 6. 初始化邀请码（管理员接口）
curl -X POST https://ask-api-xxxx.onrender.com/api/auth/admin/invite-codes?count=10 \
  -H "X-Admin-Key: 你的ADMIN_API_KEY"

7.2 TUI 打包分发

# 1. 修改 config.py 中的默认 API 地址
#    "api_base_url": "https://ask-api-xxxx.onrender.com"

# 2. 打包
cd ask-tui
./build.sh

# 3. 分发 dist/ask-tui 给朋友
# 4. 朋友收到邀请码后启动:
./ask-tui
# → 弹出激活界面 → 输入邀请码 → 开始使用

7.3 Docker 本地部署

# 构建镜像
docker build -t ask-api .

# 运行容器（挂载数据卷持久化）
docker run -d \
  -p 8000:8000 \
  -v ask-api-data:/data \
  -e LLM_API_KEY=你的密钥 \
  -e ADMIN_API_KEY=你的管理密钥 \
  -e DATABASE_URL=sqlite+aiosqlite:////data/ask_api.db \
  ask-api
